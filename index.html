What the map shows

  • MCP is the hub. Six of the other nine projects document a link to it: goose, agentgateway, Agent Router, OpenEnv, OpenSandbox and A2A. Open Responses names it once, as an example.
  • A2A is the other protocol. Its own docs call MCP vertical (deepens one agent) and A2A horizontal (connects agents). Both gateways document carrying A2A traffic: agentgateway as a feature, Agent Router as a preview guide with no dedicated A2A route type yet.
  • goose ties the context layer together. It reads AGENTS.md and loads Agent Skills, its extensions are MCP servers, and Agent Router ships an example that sends goose's model and tool calls through one gateway.
  • OpenSandbox reaches up as well as down. It serves MCP and ships its own skills as SKILL.md files for coding agents.

Open seams

  • Two gateways. agentgateway and Agent Router both route LLM and MCP traffic, and both document A2A (Agent Router as a preview guide). Agent Router's proposal 012 cites agentgateway as prior art for MCP tool naming, but no AAIF document says where one gateway ends and the other begins.
  • AGENTS.md and Agent Skills. Both put instructions in front of an agent; goose reads both. No primary document relates the two.
  • Two things called “skills”. A2A's Agent Card has an AgentSkill field that describes what an agent can do. It is unrelated to the Agent Skills format (SKILL.md), and neither project's docs mention the other's.
  • No reference architecture. AAIF has not published one. This map is built from each project's own documentation.

Stages

  • Impact: MCP, goose, AGENTS.md, Agent Skills, Open Responses.
